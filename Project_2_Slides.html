GutenSearch

A mini search engine over classic literature

Motivation

  • Everything we covered in class is one formula on one slide
  • Tokenization, inverted indexes, tf-idf, BM25, k-grams, spelling correction
  • You only see how they fit together when you build one system that uses all of them
  • I wanted a working artifact I could type into and demo, not a stack of disconnected algorithms
2

Problem Statement

Build a complete mini search engine, end to end, that

  • Indexes a real corpus of natural language documents
  • Supports Boolean, phrase, wildcard, and ranked queries
  • Offers two ranking algorithms for comparison, tf-idf cosine and BM25
  • Corrects misspelled queries
  • Runs as a deployable static website with no backend
3

Dataset

Ten public domain novels from Project Gutenberg, around 760,000 tokens total.

  • Pride and Prejudice, Jane Austen
  • The Adventures of Sherlock Holmes, Arthur Conan Doyle
  • Alice's Adventures in Wonderland, Lewis Carroll
  • A Christmas Carol, Charles Dickens
  • Frankenstein, Mary Shelley
  • Dracula, Bram Stoker
  • The Picture of Dorian Gray, Oscar Wilde
  • The Time Machine and The War of the Worlds, H. G. Wells
  • The Adventures of Tom Sawyer, Mark Twain

Downloaded directly from gutenberg.org by the build script.

4

Architecture

  • Offline part. A Python script tokenizes, builds the inverted and k-gram indexes, and writes JSON
  • Online part. A static page (HTML, CSS, JavaScript) loads the JSON and runs every query in the browser
  • No backend, no database, no server
  • Deploys straight to GitHub Pages
5

Indexing

  • Tokenization. Lowercase, alphabetic, no stemming, stopwords kept (needed for phrase queries)
  • Positional inverted index, with (doc id, sorted positions) per term
  • Delta encoded positions to shrink the JSON by about 40 percent
  • 3-gram index for wildcards, each trigram maps to its containing terms
  • Per-document length and lnc-norm precomputed at build time
6

Query Evaluation

  • Boolean. Shunting yard parser into RPN, then set intersect, union, and difference
  • Phrase. Intersect document sets, then walk positions checking consecutive offsets
  • Wildcard. Intersect k-gram lists, then regex filter to drop false positives
  • Ranked. tf-idf cosine (lnc.ltc) or BM25, returns top K results
  • Spelling. Damerau-Levenshtein over candidates passing a 3-gram Jaccard threshold

The mode is auto detected from the query string.

7

Ranking

Two ranking modes, swappable in the UI.

  • tf-idf cosine uses lnc.ltc weighting. For each query term it multiplies log scaled query tf, idf, and log scaled document tf, then normalizes by the L2 norm of both vectors
  • BM25 uses k1 = 1.5 and b = 0.75. It saturates term frequency through the k1 parameter and explicitly normalizes by document length
  • Both return the top K, where K defaults to 10 and is configurable

Conclusion and Future Work

What worked. Every class topic implemented in one working, deployable system.

What is next.

  • Porter stemming to close the run versus running gap
  • Query expansion via synonyms or pseudo relevance feedback
  • Sharded index to scale beyond ten books
  • Learning to rank with labeled relevance judgments
  • A real noisy channel spelling model trained on actual misspellings
