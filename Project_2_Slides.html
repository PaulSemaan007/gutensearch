01 · Motivation

Every algorithm in this course is one formula on one slide.

Tokenization. Inverted indexes. tf-idf. BM25. K-grams. Spelling correction. Each one gets its own lecture, its own worked example, and never quite meets the others.

You only see how they fit together when you actually build the thing and type a query into it.

02 · Problem Statement

Build a working search engine that uses everything.

  • Index a real natural language corpus
  • Support Boolean, phrase, wildcard, and ranked queries
  • Offer two ranking algorithms for comparison, tf-idf cosine and BM25
  • Correct misspelled queries
  • Deploy as a static site with no backend

03 · Methods · Dataset

Ten public domain novels from Project Gutenberg.

Around 778,000 tokens spanning gothic horror, detective fiction, social satire, science fiction, and children's literature.

05 · Methods · Indexing

A positional inverted index, plus a 3-gram index.

  • Lowercase, alphabetic tokens, no stemming
  • Stopwords stay in so phrase queries still work
  • Positions stored as deltas from the previous one
  • Roughly 40 percent smaller than absolute positions

06 · Methods · Query Evaluation

Four query modes, auto-detected from the input.

Input shapeModeHow it runs
"two words"phrasepositional posting intersection
runn*wildcardk-gram intersection, then regex filter
a AND b NOT cbooleanshunting yard to RPN, then set ops
vampire blood transylvaniarankedtf-idf cosine or BM25, top K

When a ranked query returns nothing, spelling correction kicks in. Damerau-Levenshtein edit distance over candidates that pass a 3-gram Jaccard threshold.

07 · Methods · Ranking

Two scoring schemes, one dropdown.

tf-idf cosine, lnc.ltc weighting
score(q, d) = Σt in q   (1 + log tfq,t) · log(N / dft) · (1 + log tfd,t)  /  ‖q‖2 ‖d‖2
BM25, with k1 = 1.5 and b = 0.75
score(q, d) = Σt in q   idf(t) · (k1 + 1) tfd,t  /  (tfd,t + k1 (1 − b + b · |d| / avgdl))

Both rankers return the top K. K defaults to 10 and is configurable in the UI.
